<center>
🌋 Basalt Chat
</center>

Basalt Chat — это изолированный форк официального мобильного клиента Telegram (Android/iOS), переработанный под принципы Closed-Loop Security (безопасность замкнутого контура). Проект устраняет зависимость от публичных серверов Telegram.org и заменяет стандартную SMS-верификацию на строгую парольную авторизацию с проверкой по собственной базе данных. Это решение предназначено для корпоративных сред, приватных сообществ и систем, требующих полного контроля над списком пользователей.

>⚠️ Важно: Basalt Chat несовместим с официальной сетью Telegram после этапа входа. Все сообщения хранятся и передаются только через вашу инфраструктуру.

<center>

✨ Ключевые особенности

</center>

1.🔒 Закрытая система регистрации (Invite-Only)
2.Административный контроль: Самостоятельная регистрация пользователями заблокирована. Доступ получают только те, чьи номера телефонов были предварительно внесены администратором в базу данных.
3.Отсутствие SMS-кодов: Стандартный механизм получения кода подтверждения полностью удален из логики клиента.
5.Строгая валидация: При попытке входа номер телефона проверяется на наличие в "Белом списке". Если номер отсутствует — доступ немедленно отклоняется без лишних уведомлений.
6.🔑 Парольная авторизация вместо OTP
7.Статические пароли: Вместо 5-значного кода пользователь вводит свой личный пароль.
8.Жесткие ограничения: Максимальная длина пароля — 32 символа. Допускаются буквы, цифры и разрешенные спецсимволы (!"№;%:?*()_+=-).
9.Хеширование: Пароли никогда не хранятся в открытом виде. На стороне бэкенда используется безопасное хеширование перед сравнением с данными в TiDB.

<center>

🛡 Изоляция сети (Air-Gapped Logic)

</center>

Клиент модифицирован таким образом, что все запросы аутентификации идут не на серверы Telegram, а на ваш собственный API Gateway.
После успешной авторизации состояние сессии поддерживается локальным токеном, привязанным к устройству и пользователю.

<center>

🏗 Архитектура системы

</center>

Система состоит из трех основных компонентов:
1.Клиент (Mobile App): Форк исходного кода Telegram Android/iOS с патчами в слое MTProto/TDLib.
2.API Gateway (Backend): Промежуточный сервис (Go/Python/Node.js), который принимает запросы от клиента и взаимодействует с базой данных.
3.База Данных (TiDB): Распределенная SQL база данных, хранящая список разрешенных пользователей и их хешированные пароли.


Схема потока авторизации
Пользователь открывает приложение и вводит номер телефона.
Клиент отправляет HTTP-запрос на ваш Backend API с этим номером.
Backend проверяет наличие номера в таблице users базы данных TiDB.
Если номер НЕ найден: Возвращается ошибка доступа. Клиент показывает сообщение об отказе во входе.
Если номер НАЙДЕН: Возвращается статус "Требуется пароль". Клиент переключает интерфейс на экран ввода текстового поля вместо цифрового кода.
Пользователь вводит пароль (максимум 32 символа).
Клиент отправляет номер и введенный пароль на Backend.
Backend хеширует полученный пароль и сравнивает его с сохраненным хешем в TiDB.
Если хеши совпадают: Выдается токен сессии. Клиент переходит в основной интерфейс мессенджера.
Если хеши разные: Возвращается ошибка неверных учетных данных.
💾 Структура данных (TiDB Schema)
Данные хранятся в таблице users. Ниже приведена логическая структура записи, соответствующая вашему формату JSON:
id (BIGINT): Уникальный идентификатор записи для быстрого поиска. Не влияет на бизнес-логику.
phone (VARCHAR(20)): Номер телефона в строгом формате E.164 (например, +79991234567). Используется как уникальный ключ для проверки наличия пользователя.
display_phone (VARCHAR(30)): Человекочитаемый формат номера для отображения в интерфейсе (например, +7-999-123-45-67).
password_hash (VARCHAR(255)): Безопасный хеш пароля (Argon2id или Bcrypt). Исходный пароль в базе не хранится.
created_at (TIMESTAMP): Дата и время создания аккаунта администратором.
is_active (BOOLEAN): Флаг активности. Позволяет мгновенно блокировать доступ к аккаунту без удаления данных.
Пример логической структуры одной записи:
ID: 1
Phone: +77777777777
Display Phone: +7-777-777-77-77
Password Hash: [Защищенный хеш строки "therichnumber_ru"]
🛠 Техническая реализация
1. Модификация Клиента (C++ / Java / Kotlin)
Основная работа выполнена в слое взаимодействия с сетью:
Перехват auth.sendCode: Вызов нативной библиотеки заменен на HTTP-запрос к вашему бэкенду.
UI Changes: Экран ввода кода переиспользован под поле ввода текста (пароля) с масками и валидацией длины (не более 32 символов).
Session Management: Реализован кастомный менеджер сессий, который хранит токен доступа после успешного логина.
2. Бэкенд Сервис
Сервер разработан с упором на производительность и безопасность:
Rate Limiting: Ограничение количества попыток ввода пароля (например, 5 раз в минуту с одного IP) для защиты от Brute-force атак.
Input Sanitization: Жесткая фильтрация спецсимволов при приеме пароля от клиента согласно вашим правилам.
Connection Pooling: Эффективное использование соединений с TiDB для минимизации задержек.

🔐 Безопасность
Шифрование трафика: Все соединения между клиентом и бэкендом защищены TLS 1.3.
Защита от MITM: Используется Certificate Pinning в мобильном клиенте. Подключение возможно только к доверенным сертификатам вашего сервера.
Аудит действий: Каждая попытка входа (успешная и неуспешная) логируется в отдельную таблицу audit_log в TiDB с указанием IP, Device ID и Timestamp.
